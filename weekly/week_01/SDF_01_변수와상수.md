## 정리
고수준 언어로 프로그램을 작성할 때
값을 저장함에 있어 그 성격에 따라 크게 3 가지로 나뉜다.

1. 변수
2. 읽기 전용 변수
3. 상수

상세 내용 전에 유의할 것은 이건 어디까지나 컴파일러에서 제공하는 규칙에 따라 발생하는 개념이라는 점.
예를 들어, 읽기 전용 변수라고 해서 실제로 해당 변수 메모리에 다른 값이 들어갈 수 없는 건 아님.
단지, 컴파일러에서 컴파일 시점에 다른 값을 넣으려고 하는 시도를 막아준다.
즉, 컴파일러와 고수준 언어 사이에 존재하는 계약

__변수__는 말 그대로 변할 수 있는 값이다.
메모리에 값이 할당된 이후에도 언제든 새로운 값이 들어갈 수 있다.
__읽기 전용 변수__는 한 번 값이 할당된 이후에는 다른 값이 들어갈 수 없다.
__상수__는 보통 컴파일시점부터 값이 확정된다.
읽기 전용 변수와의 차이점이라면, 초기화 시점이다. 읽기 전용 변수는 컴파일 시점에 값이 확정되지 않을 수 있지만
상수는 값 자체가 리터럴하게 사용되기 때문에 컴파일 시점에 보통 값이 확정된다.
```
final int a = sum(); // 읽기 전용
const int a = 3; // 상수
```

이러한 형태가 프로그램 개발에 있어 어떤 이득이 있을까?
1. 디버깅 효율성 증가
2. 메모리 효율성 증가(최적화)

이러한 규약이 없으면 개발자는 매번 변수에 어떤 값이 들어있는지 런타임에서 힘들게 디버깅해야한다.
하지만, 이런 규약을 통해 정말 필요한 변수만 값을 확인함으로써 디버깅 효율성을 줄일 수 있다.
(더불어 읽는 사람으로 하여금 주석 없이도 의도를 전달하는 효과도 준다.)

뿐만 아니라, 상수는 메모리 사용 없이 리터럴하게 사용되고, 읽기 전용 변수도 레지스터 안에서만 저장됨으로써
메모리 사용 효율성 + 최적화를 가능하게 해준다.
